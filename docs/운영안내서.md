# KSLC 홈페이지 운영 안내서

이 문서는 **홈페이지를 넘겨받는 사람**을 위한 것입니다. 기술 용어는 최대한 줄였습니다.
읽는 순서대로 따라가면 됩니다. 모르는 게 나오면 **"무엇을 하지 말아야 하는지"** 부분만이라도 꼭 보세요.

- 홈페이지: https://www.kslcampus.org
- 마지막 정리: 2026년 10월 12일

---

## 1. 이 홈페이지가 하는 일

단순한 소개 페이지가 아닙니다. **어르신이 도움을 요청하면 그것을 접수하는 창구**입니다.

```
어르신이 '상담 요청' 양식을 작성
      ↓
① 구글 스프레드시트에 기록이 남습니다   ← 먼저 저장
      ↓
② 같은 자리에서 구글이 알림 메일을 보냅니다
     · info@kslcampus.org 로 담당자 알림
     · 어르신에게 접수 확인 메일 (접수번호 포함)
      ↓
③ 혹시 ②가 실패하면, 홈페이지가 예비 메일 경로로 다시 보냅니다
```

**메일 길이 두 개인 이유:** 2026년 10월에 구글 앱 비밀번호가 조용히 폐기되어
알림이 몇 주 동안 끊긴 적이 있습니다. 지금은 구글이 자기 권한으로 직접 보내므로
만료될 비밀번호가 없고, 그래도 안 되면 예비 경로가 받아줍니다.

**①을 ②보다 먼저 하는 것이 중요합니다.** 메일이 고장나도 신청 기록은 남아야 하기 때문입니다.
2026년 9월에 받는 메일함이 죽어 있어서 신청이 조용히 사라진 일이 있었고, 그 뒤로 이렇게 바꿨습니다.

**그래서 가장 중요한 점검은 "사이트가 예쁘게 보이는가"가 아니라 "신청이 실제로 접수되는가"입니다.**

## 3. 내용을 바꾸고 싶을 때

### 쉬운 것 (글·사진)

| 바꾸려는 것 | 어디 |
|---|---|
| 소식·언론보도 | `lib/news.ts` 의 `newsItems` |
| 유튜브 영상 | `lib/news.ts` 의 `videoItems` (영상 주소의 11글자 ID만) |
| 이사·직원 명단·사진 | `lib/leadership.ts` |
| 상단 공지 배너 | `lib/notices.ts` ← **끝나는 날짜를 꼭 적으세요** |
| 자료실 파일 | `public/downloads/` 에 넣고 `app/(ko)/ko/resources/page.tsx` + `app/(en)/resources/page.tsx` |
| 사진 파일 | `public/team/`, `public/press/` |

각 파일 맨 위에 한국어 설명과 **복사해서 쓸 수 있는 예시**가 들어 있습니다.

### 공지 배너는 반드시 날짜와 함께

```
showUntil: "2026-10-10"   ← 이 날짜가 지나면 배너가 스스로 사라집니다
```

사람이 기억해서 내릴 필요가 없습니다. 2026년 10월에 지난 행사 배너가 이틀 동안
걸려 있던 일이 있어서, 그 뒤로 날짜를 적게 만들었습니다. **날짜를 비우지 마세요.**

### 어려운 것 (사람이 필요합니다)

새 페이지 만들기 / 디자인·배치 변경 / 메뉴 구조 변경 / 상담 양식 항목 추가·삭제 / 고장 수리

## 4. 절대 하지 말아야 하는 것

1. **저장소(GitHub)를 비공개로 바꾸지 마세요.**
   비공개로 바꾸면 **배포가 멈춥니다.** 지금 요금제에서는 공개 저장소만 자동 배포됩니다.
2. **비밀번호·암호가 든 파일을 저장소에 올리지 마세요.**
   저장소는 **누구나 볼 수 있습니다.** `.env`, `*.ready.gs` 같은 파일은 올라가지 않도록
   막아뒀지만, 새 파일을 만들 때는 조심하세요.
3. **`master`에 바로 올리지 말고 미리보기로 먼저 확인하세요.** (아래 6번)
4. **커밋 메시지에 `Co-Authored-By` 줄을 넣지 마세요.** 배포가 거부됩니다.
5. **상담 양식과 관련된 파일은 손대지 마세요.**
   `app/api/`, `lib/submissions.ts`, `lib/formSchema.ts`, `components/ConsultationForm.tsx`
   → 여기가 고장나면 **눈에 보이지 않게** 신청이 사라집니다. 반드시 담당 개발자에게.

## 5. 자동 점검 (안전장치)

사람 눈에 보이지 않는 고장을 잡기 위한 장치입니다.

**매주 월요일 오전 9시**, 구글이 홈페이지에 점검을 요청하고 이렇게 확인합니다.

1. 홈페이지가 응답하는가
2. 스프레드시트에 기록이 남는가
3. **구글이 점검 메일을 보내는가** (평소 알림이 나가는 길)
4. 예비 메일 경로에 아직 로그인이 되는가 (앱 비밀번호 만료를 잡습니다)
5. **점검 메일이 info@ 메일함에 실제로 도착하는가** ← 가장 중요

하나라도 실패하면 `[KSLC 긴급]` 경고 메일이 옵니다.
경고 메일은 홈페이지가 아니라 **구글이 직접** 보냅니다. 홈페이지 메일이 고장난
상황에서도 경고는 도착해야 하기 때문입니다.

기록은 상담기록 스프레드시트의 **`자동점검` 탭**에 쌓입니다.

### 설치 (아직 안 했다면 한 번만, 5분)

> **어느 계정으로 설치하는지가 중요합니다.** 4번 점검은 info@ 메일함을 직접 들여다보기
> 때문에, 이 스크립트는 `info@kslcampus.org` 계정으로 설치해야 합니다. 다른 계정으로
> 설치하면 4번은 "확인불가"로 표시되고 1~3번만 점검됩니다 (헛경고는 가지 않습니다).

`docs/apps-script-watchman.gs` 파일 맨 위의 설치 설명을 따라가세요.
요약: 스프레드시트 → 확장 프로그램 → Apps Script → 새 스크립트에 붙여넣기 →
`SECRET` 채우기 → `setup` 함수 한 번 실행.

### 직접 점검해보고 싶을 때

가장 확실한 방법은 **직접 상담 요청을 한 건 넣어보는 것**입니다.
확인 메일이 오고 스프레드시트에 줄이 생기면 정상입니다.

## 6. 미리보기 — 실수를 막는 가장 쉬운 방법

변경을 **바로 라이브에 올리지 않고** 임시 주소에서 먼저 보는 기능입니다. 공짜입니다.

```
변경을 'master' 가 아닌 새 가지(branch)에 올림
      ↓
Vercel 이 임시 주소를 만들어 줍니다 (예: kslc-xxxx.vercel.app)
      ↓
그 주소를 열어서 눈으로 확인
      ↓
괜찮으면 master 에 합치기  →  실제 사이트 반영
```

> **먼저 한 번만 확인할 것:** 미리보기 주소는 기본 설정에서 **Vercel 에 로그인한 사람만**
> 열립니다. 로그인하지 않은 사람에게는 로그인 화면이 나옵니다. 홈페이지 담당자가 Vercel
> 계정 없이 미리보기를 봐야 한다면, Vercel → 프로젝트 → Settings → **Deployment Protection**
> → **Vercel Authentication** 을 꺼야 합니다. (지금 요금제는 팀원이 1명뿐이라 초대로는
> 해결되지 않습니다.) 끄면 주소를 아는 사람만 볼 수 있는 상태가 되고, 검색에는 걸리지 않습니다.
>
> 2026-10-12 확인: 미리보기 배포 자체는 정상 작동합니다.

**AI에게 수정을 맡길 때는 이 방법을 쓰세요.** AI가 "다 됐습니다"라고 해도,
임시 주소를 직접 열어보기 전까지는 믿지 마세요.

그리고 **코드가 잘못되면 배포 자체가 실패하고 기존 사이트는 그대로 유지됩니다.**
사이트가 깨진 채로 올라가는 일은 구조적으로 막혀 있습니다.

## 7. 계정과 비용

| 무엇 | 어디 | 비용 | 없으면 |
|---|---|---|---|
| **도메인** kslcampus.org | (회장님 관리) | 연 $15~20 | **사이트·명함·기사 링크 전부 사망.** 가장 중요 |
| **구글 Workspace** info@ | Google | 기존 | 메일·스프레드시트 정지 |
| **GitHub** (코드 보관) | github.com | 무료 | 배포 중단 (코드 사본 있으면 복구 가능) |
| **Vercel** (사이트 운영) | vercel.com | 무료 | 사이트 중단 |

**잃어버렸을 때 복구가 불가능한 것은 도메인뿐입니다.** 코드는 사본만 있으면 하루면 되살립니다.
그래서 도메인 자동갱신과, 코드 사본을 단체 구글 드라이브에 두는 것이 가장 값싼 보험입니다.

### 비밀값 7개

실제 값은 **Vercel 안에만** 있습니다 (Settings → Environment Variables).
이름만 `.env.example` 에 적어뒀습니다. 사이트를 다른 곳으로 옮기면 **이 7개를 다시 넣어야 합니다.**
빠뜨리면 사이트는 멀쩡해 보이는데 **상담 신청만 조용히 실패합니다.**

## 8. 고장났을 때

| 증상 | 먼저 확인 |
|---|---|
| 사이트가 안 열림 | 도메인 갱신 여부 → Vercel 상태 |
| 바꿨는데 반영이 안 됨 | 배포가 실패했을 가능성. Vercel 화면에서 빨간 표시 확인 |
| 상담 신청 메일이 안 옴 | `자동점검` 탭 확인 → 양식을 직접 한 건 제출해보기 |
| `[KSLC 긴급]` 메일 받음 | 그 메일을 담당 개발자에게 그대로 전달 |

**혼자 고치려 하지 마세요.** 특히 상담 양식 쪽은, 고치려다 더 조용한 고장을 만들기 쉽습니다.
